# Delivery explanation

- What problem was solved, and which requirements are satisfied?
- How can the recipient run or use the result?
- Trace one real input through processing to the final output.
- Why was the consequential design choice made? What alternative was considered?
- Which checks actually ran, on which artifacts, with what result?
- What remains unverified, unsupported or limited?
- For recurring outputs: who updates/regenerates/delivers them, where and when, and how is stale output recognized? Mark unconfirmed operating conditions.
- If the requirement changes, which component or assumption must change first?

Use the task's required submission format. In a competition, practice explaining this before submission; do not use AI during the prohibited written-answer phase.
