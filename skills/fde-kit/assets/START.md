먼저 요청 크기에 맞춰 진행해줘. 설명·상태 질문은 필요한 근거만 확인해 대화로 답하고, 작은 수정은 관련 파일·기존 요구·영향받는 검사만 다뤄줘. 매 요청마다 전체 자료 분석·인터뷰·계획·작업 등록·검증·handoff를 반복하지 마. 새 과제나 중요한 요구 변경, 여러 단계 작업 재개일 때 아래 절차를 적용해줘. 기존 작업의 파일이 바뀌면 검증 무효화와 필요한 재검증은 지켜줘.
여러 단계 작업을 시작하거나 재개할 때 이 프로젝트의 AGENTS.md, 실제 과제 README·제출 안내·제공 입력과 관련 fde-notes를 확인해줘. 키트의 README나 예제를 실제 과제로 혼동하지 마. 필요한 자료가 없으면 위치를 요청하고 요구를 만들어내지 마.
프로필이 competition이면 설치된 .agents/skills/fde-kit/references/profiles.md의 대회 제한을 먼저 읽어줘. Computer Use(자동 조작)는 전 단계에서 금지되며, Astra 사용 제한을 지켜야 해. 제공 환경의 허용된 모델인지 확인하고, Astra가 선택되어 있으면 플랫폼의 정식 모델 선택 기능으로 변경하도록 안내해줘. 계정·키·관리 설정을 바꾸거나 제한을 우회하지 마. 이 대회 제한을 standard 프로젝트에 일괄 적용하지 마.
공식 채점표가 있으면 출처와 항목을 연결하고, 없으면 배점이나 숨은 기준을 추측해서 만들지 마.

먼저 필수 산출물·요구사항·제약을 정리하고 실제 데이터를 읽어줘. 구조·대표 값·누락·중복뿐 아니라 자료가 다루는 기간·집단·채널과 빠진 상황도 확인해줘. 관측되지 않은 상황을 0이나 문제없음으로 해석하지 마.
기존 BRIEF에 요구 ID/원문 위치 → 산출물·동작 → 데이터 근거와 한계 → 구현 선택지·장단점 → 미정/명시됨/확정/위임 상태와 질문 상대 → 검사 조건을 연결한 구현 명세 초안을 작성해줘. 원문 요구·관측 사실·담당자 설명·내 선택·네 제안을 구분해줘. 처음부터 확정본인 것처럼 쓰지 말고 답변을 받으며 갱신해줘.
새 과제의 첫 답변에는 산출물과 중요한 데이터 관찰, 구현 명세 초안을 보여주고, 중요한 미확정이 있을 때만 다음 질문 하나를 해줘. 문구·색상·배치와 동등한 내부 구현은 기본적으로 맡길게. 기존 요구·디자인·접근성·업무 의미를 지키며 결정하고 사소한 선택마다 질문·기록하지 마. 업무 규칙·제약·필수 기능·권한·개인정보·입력 허용/거부·중요 기본값과 예외 동작처럼 실제 결과나 위험을 바꾸는 미정 사항은 확인해줘. 이미 자료나 내 답변으로 정해진 것은 다시 묻지 마.
파일만으로 알 수 없는 실제 실패·시간대별 수요 변화·기록되지 않는 상황·운영 제약은 담당자 AI에게 물을 중립적인 질문으로 준비해줘. 특정 요일 혼잡을 가정하지 마. 내가 메신저를 조작해야 하는 환경이면 전달할 질문을 주고 답변을 기다려줘. 담당자 설명은 측정값이나 기능 추가 승인으로 바꾸지 말고, 어떤 명세 항목을 바꾸는지 짚은 뒤 구현 방안은 내 선택으로 확정해줘.
필요한 중요 질문은 한 번에 하나씩 해줘. 업무 결과에 영향을 주는 선택에는 대안·장단점·추천 이유를 설명하고 내 답을 기다려줘. 기존 운영 사실·업무 규칙은 중립적으로 물어줘. 추천은 내 결정으로 간주하지 마. 기본 위임된 표현 세부사항은 질문 없이 진행하고, 새 중요한 불확실성만 같은 방식으로 확인해줘.
중요 질문·답변 주체·출처·관련 명세 ID·확정/위임/미정 상태를 기존 DECISIONS에 기록하고, 확정된 규칙과 검사 조건은 BRIEF와 관련 계약에 반영해줘. 기본 위임된 색상·문구마다 기록을 만들지 말고 새 세션에서도 답변을 재사용해줘. 시간이 부족하거나 내가 구현을 요청했다는 이유로 중요한 업무 규칙을 가정하지 마. 답을 기다리는 동안에는 그 결정에 영향받지 않는 허용된 작업을 진행해줘.
이미 내가 요청한 단계가 분명하면 그 범위 안에서는 구현·검증까지 진행해도 돼. 필수 조건을 만족하는 가장 작은 전체 동작 경로를 먼저 완성하고 선택 개선은 이후에 해줘. 최적화 자체가 필수면 처음부터 포함하고 강제 조건을 뒤로 미루지 마. 통합·검증·제출 시간을 남겨줘.
아직 구현을 요청하지 않았다면 전체 과제를 자동으로 구현하거나 다른 에이전트에 넘기지 마.
문제 정의와 계획을 요청했다면 질문이 끝날 때 같은 BRIEF에서 전체 구현 계획을 종합해줘. 목표·필수/제외 범위, 사용자 흐름·예외, 데이터, 핵심 규칙·제약, 필요한 구성, 구현 순서와 검증 사례를 명세 ID로 연결하고 전체 준비 여부와 남은 미확정을 밝혀줘. 첫 작업만 준비된 것을 전체 계획 완료로 보지 마. 계획을 전달한 뒤 제품 코딩은 시작하지 마.
방향·우선순위·범위 변경과 최종 제출은 내가 결정할게. 작은 실행 단계마다 허락을 다시 묻지는 마.

추가 요청은 기존 코드·테스트·산출물·BRIEF·DECISIONS를 갱신하는 것을 기본으로 해줘. 요청이나 단계마다 새 작업 폴더·버전 사본·계획서·분석서·요약서를 만들지 마. 설명·상태·검토는 기본적으로 대화로 답하고, 필수 산출물·실제 책임 분리·반복 사용할 검사/도구에 필요한 파일만 추가해줘. 일회성 점검은 직접 만든 임시 공간에서 수행하고 종료 전에 경로·소유권·참조를 확인해 정리해줘. 원문·사용자 파일·검증 로그와 참조 산출물은 보존해줘. 자세한 기준은 execute.md의 파일 재사용 규칙을 적용해줘.
작은 작업은 기존 문서·짧은 BRIEF와 작업 계약 하나를 사용하고 verify --handoff로 기록해줘. 같은 산출물의 추가 요구는 기존 계약을 갱신하고 변경된 동작을 검사해줘. 유효한 검사를 기록용으로 반복하거나 파일 수를 줄이려고 필요한 코드 분리·검증 근거를 없애지는 마.
