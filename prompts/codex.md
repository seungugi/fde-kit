# Codex용 프롬프트

설치된 fde-kit의 지침을 사용한다. 필요한 블록 하나만 고르고 이후에는 평소 말로 이어간다. C1은 계획만, C3은 구현까지 요청한다. C2는 답변 전달이며 새로운 구현 범위를 승인하지 않는다. 작은 수정이나 상태 질문은 이 흐름을 다시 시작하지 않는다.

## C1. 문제 정의 시작

```text
$fde-kit
지금은 요구사항 분석과 계획만 해줘.
과제 원문·입력 위치: [경로 또는 원문]
시간·환경·제출 조건: [알려진 내용, 나머지는 미확인]

실제 자료를 읽고 같은 BRIEF에 요구 출처·데이터 근거와 한계·업무 용어·전체 사용자 흐름·검사 조건을 연결한 초안을 보여줘. 담당자에게 확인할 운영 사실과 내가 정할 제품 선택을 구분해 중요한 미정만 묻고, 답변을 받으며 갱신해줘.
최종 계획은 시연 가능한 작은 기능으로 나누고 각 기능의 요구 ID·의존관계·검사 조건을 연결해줘. 일부 기능의 준비와 전체 계획의 준비를 구분하고, 계획을 전달한 뒤 제품 구현은 시작하지 마.
```

## C2. 담당자 답변 반영·다음 질문

```text
추가 답변: [원문·질문 ID·답변 주체/출처]

기존 요구와 대조해 이 답이 실제로 바꾸는 규칙·데이터·흐름·검사를 짚어줘. 충돌이나 중요한 미정만 확인하고 같은 BRIEF·DECISIONS와 영향받는 작업 계약을 갱신해줘. 보고된 사실을 측정값이나 내 기능 추가 승인으로 바꾸지 마.
현재 요청 범위를 유지해줘. 계획 단계면 계획을 갱신하고, 이미 구현을 맡긴 범위면 준비된 독립 기능을 이어가줘. 정해진 내용의 재질문이나 새 계획서는 필요 없어.
```

## C3. 범위 확정·구현 또는 분석 실행

```text
$fde-kit
실행할 범위: [기존 BRIEF의 요구/작업 ID 또는 목표·입력·산출물·완료 조건]
추가 제약·제외 범위: [있을 때만]

확정된 요구를 화면·서버·저장·검사가 연결된 작은 기능으로 구현해줘. 웹이 필요 없는 작업은 필요한 입력→처리→결과 경로만 연결해줘. 필수 조건을 만족하는 첫 기능을 완성하고 검사한 뒤 다음 기능으로 진행해줘.
기존 코드·문서·테스트·작업 ID를 재사용하고 중요한 새 미정은 의존 작업만 보류해줘. 요구 변경은 명세·계약·검사에 함께 반영해줘. 단계마다 다시 허락을 묻지 말고 요청 범위의 구현·필요한 통합 검증·사용 안내까지 마쳐줘.
실제 검사와 요구 충족/코드 품질 검토를 구분해 결과·남은 한계를 알려줘. 유효한 검사를 기록용으로 반복하지 말고, 외부 전송·배포·제출 권한은 가정하지 마.
```

## C4. 결과 검증·구체적인 약점 확인

```text
$fde-kit
현재 결과를 원래 요구와 완료 조건에 대조해 검증해줘.
기존 근거의 유효성을 확인하고 변경되거나 아직 확인하지 못한 중요한 동작을 검사해줘. 요구 누락·불필요한 기능·상태/권한/예외 처리와 구현 품질을 함께 검토해줘. 테스트 통과로 실제 화면 확인이나 사람의 승인을 대신하지 마.
확인한 범위·구체적 실패·미확인을 구분해 대화로 설명해줘. 검토 요청만으로 구현 범위를 확대하지 마.
```

## C5. 오류 원인 파악·최소 수정

```text
$fde-kit
다음 동작에서 문제가 생겼어.
실행한 작업과 입력: [재현 정보]
기대 결과: [원래 요구]
실제 결과 또는 오류: [관찰 내용·로그 위치]

가장 작은 재현 사례로 원인을 좁히고 요청 범위 안에서 수정해줘. 원인 가설과 근거를 구분하고, 새 증거 없이 같은 명령이나 추측성 수정을 반복하지 마. 관련 없는 구조 변경은 하지 마.

수정 후 원래 실패 사례와 영향받는 중요한 동작을 실제로 검사해줘. 실패 로그를 지우거나 이전 성공 기록으로 대체하지 말고, 현재 코드·입력에 대한 검증과 handoff를 갱신해줘. 마지막에는 원인, 바꾼 부분, 확인 결과와 남은 불확실성만 짧게 정리해줘.
```

## C6. 시간이 부족할 때 범위 조정

```text
$fde-kit
남은 시간은 [시간]이고 제출 조건은 [조건]이야.

현재 구현과 검증 상태를 기준으로 필수 완료 조건, 아직 위험한 부분, 미뤄도 되는 기능을 구분해줘. 구현됐다는 이유만으로 검증까지 끝났다고 보지 마. 알 수 없는 작업 시간을 확정값처럼 말하지 마.

필수 결과와 마지막 검증·제출 시간을 지킬 수 있는 최소 범위 하나를 추천하고, 무엇을 포기하며 어떤 영향이 있는지 설명해줘. 실제 안내에 없는 배점으로 우선순위를 만들지 마. 이 요청에서는 조정안만 제시하고, 범위 변경은 내가 선택한 뒤 적용해줘.
```

## C7. 세션 종료·인계

```text
$fde-kit
여기까지 작업을 정리해서 다음 세션이 이어갈 수 있게 해줘. 새 기능은 만들지 마.

현재 파일과 실제 검증 상태를 확인하고, 목표·합의한 범위·산출물 위치·검사 근거·남은 문제·다음 행동 하나를 기존 기록에 남겨줘. 요구가 바뀌지 않았다면 진행 보고 때문에 BRIEF를 다시 쓰지 말고 DECISIONS를 사용해줘. 중복 요약 문서를 추가하지 마.

지금 답을 기다리는 질문, 아직 묻지 않은 미정 사항, 이미 확정된 답변과 출처, 명시적으로 위임한 범위도 DECISIONS에 유지해줘. 바뀐 결정은 이전 답변을 지우지 말고 무엇으로 대체됐는지 남겨줘.

반복 사용할 결과라면 누가 어느 환경에서 언제 원본을 수정하고 생성·전달하는지, 최신 결과를 어떻게 구별하는지도 짧게 남겨줘. 확인되지 않은 운영 책임이나 권한은 미확인으로 표시해줘. 현재 상태에 맞는 handoff를 생성하고 다음 세션에서 처음 읽을 위치를 알려줘.
```

## C8. 새 세션에서 재개

```text
$fde-kit
이 프로젝트를 이어가줘. 현재 요청 또는 이전 합의에서 달라진 내용은 [없음 / 변경 내용]이야.

AGENTS.md와 실제 과제, BRIEF·DECISIONS를 읽고 status를 실행한 뒤 HANDOFF를 대조해줘. 이전 세션의 완료 주장이나 저장된 상태만 믿지 말고 현재 입력·코드·검사·결과의 근거가 유효한지 확인해줘. 추가되거나 등록에서 빠진 관련 파일도 살펴봐줘. 대회라면 현재 안내와 competition 제약을 적용해줘.

현재 목표, 실제 검증된 범위, 남은 핵심 문제와 다음 행동 하나를 짧게 설명한 뒤 이미 승인된 작업을 진행해줘. 기존 답변을 다시 묻지 말고 중요한 업무 미정 사항이 있을 때만 현재 답할 수 있는 질문을 한 번에 모아서 이어가줘. 문구·색상·배치의 기본 위임과 사용자가 정한 예외를 재사용해줘. 표현 위임을 업무 규칙 변경으로 확대하지 말고 불필요한 재설치·전체 재작성·성공 검사 반복은 하지 마.
```

## C9. AI 사용 허용 단계의 설명 연습

```text
$fde-kit
AI 사용이 허용된 준비·작업 단계에서 내가 결과를 이해했는지 연습하고 싶어. 실제 AI 금지 후속 서술형이라면 답안 작성·첨삭·문제 풀이를 하지 마.

현재 결과를 근거로 내가 설명해야 할 중요한 질문을 하나씩 해줘. 입력이 결과로 바뀌는 흐름, 중요한 설계 선택과 대안, 실제 검사 범위, 구체적인 약점과 영향, 다음 개선 중 필요한 것을 골라줘.

먼저 모범 답안을 주지 말고 내 답을 기다려줘. 답을 받으면 코드·문서·검사 결과와 다른 부분을 짚고 필요한 만큼만 설명해줘. 숨은 채점 기준·예상 점수·존재하지 않는 약점을 만들어내지 마.
```
