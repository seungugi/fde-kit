# 요구에서 정한 기대값과 그럴듯한 오답

이것은 검증 설계용 합성 예제이며 운영 도구나 보편적인 교대 규칙이 아니다. 실제 과제에는 원래 요구와 독립적으로 확인한 기대값을 사용한다. 생성 프로그램을 불러 기대값을 다시 계산하지 않는다.

이 예제의 합의: 결과 순서는 R1, R2, R3이고 아래 세 값을 정확히 보존해야 한다.

| ID | 확인한 사실 | status | remaining |
|---|---|---|---|
| R1 | 출력만 끝났고 부착이 남음 | pending | Attach labels |
| R2 | 현장 결과의 최종 완료가 확인됨 | complete | 빈 문자열 |
| R3 | 인수 이후 수량이 변경돼 재확인이 필요함 | review | Confirm changed quantity |

이 폴더에서 `python check_result.py result.json`은 종료 코드 0이다. result.json의 **복사본**에서 R1의 status를 complete로, remaining을 빈 문자열로 바꾸면 JSON 문법·행 수·ID가 모두 맞아도 종료 코드 1이어야 한다. 파일을 읽을 수 없거나 JSON이 잘못되면 2다. 검사 실패는 fde.py verify에서도 실패로 남는다.

배포본 최상위에서 `python demo_negative_check.py`를 실행하면 임시 복사본으로 정상/오염 검사를 모두 실행하고 원본을 보존한다. 설치된 스킬에는 이 예제 폴더가 함께 있으므로 별도 다운로드 없이 복사해 사용할 수 있다.

이 예제는 세 개의 알려진 사례에 대한 검사다. 실제 제품에서는 원본 자료·업무 규칙·예외에 맞게 검사 범위를 확장해야 한다. 파일 해시나 생성 명령 성공만으로 이러한 업무 기대값을 대신할 수 없다.
