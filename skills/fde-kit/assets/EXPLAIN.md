# Result-grounded delivery explanation

Use this outline only for a requested/required document, adapting existing documentation. Otherwise explain in the conversation. Fill from the actual artifacts; omit irrelevant sections and keep missing evidence explicit. The procedure lives in [Explain](../references/explain.md).

## Result and mechanism

- Problem, mandatory requirements, current completion boundary and artifact/input version.
- Consequential choice: how it works → requirement/data basis → viable alternative → difference and accepted cost. Identify recorded reasons versus retrospective inference and unmeasured comparisons.

## One input through the system

| Input/action | Actual file/function | Transformation or rule | Group key / state / storage | Output and next consumer |
|---|---|---|---|---|

Trace one real accessible case. Mark any illustrative data as hypothetical. Include only the UI, interfaces, grouping and persistence that exist in this result.

## What works and how to check it

| Behavior/claim | Implementation or output reference | Implemented / demo / assumed / missing | Actual check and evidence, or untested | Reproduction and expected observation |
|---|---|---|---|---|

Give working directory, environment, inputs/settings and real commands. Separate commands actually run from suggested checks, and state untested boundaries.

## Normal and failure paths

| Case/trigger | Detecting component | Response/output | State retained or rolled back | Recovery and actual evidence/gap |
|---|---|---|---|---|

## Claims, limits and next check

- For a numerical claim: source scope, units, formula/denominator, exclusions and comparable baseline. What does the evidence support, and what would be an overclaim?
- Independent check: source-rule expectation, raw-data recomputation or operating evidence; distinguish performed checks from proposals.
- Main tradeoff or operating limit, affected behavior, and next check that could change the conclusion. Include sensitivity/side effects where relevant; do not invent metrics for a nonnumeric result.
- Startup/use and, for recurring outputs, actual owner, environment, refresh trigger and stale-output detection. Mark unknowns.

Optional understanding practice uses these artifacts after explanation, or quiz-first only if requested. AI assistance must end before an AI-prohibited assessment phase; this outline is for permitted preparation and handoff.
