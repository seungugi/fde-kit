# 업무 담당자 AI와 대화할 프롬프트

상대에게 이미 주어진 업무 역할과 정보를 존중한다. S1은 첫 메시지이고, 이후에는 실제로 필요한 질문 하나만 고른다. 담당자의 답을 Codex에 전달할 때 질문과 자료의 출처도 함께 옮긴다.

## S1. 최근의 구체적인 문제 사례

```text
말씀하신 업무를 개선할 결과물을 만들기 전에 실제로 해결해야 할 문제부터 이해하고 싶습니다. 현재 담당하시는 업무와 알고 계신 정보를 기준으로 답변해 주세요.

질문은 한 번에 하나씩 이어가겠습니다. 확인된 사실과 추정·의견을 구분하고, 모르거나 확인이 필요한 내용은 그대로 말씀해 주세요. 공식 규칙과 실제 관행이 다르면 차이를 알려주세요. 제가 제안하거나 요약한 내용이 현장과 맞지 않으면 이유나 반례를 말씀해 주세요. 근거 자료가 있다면 확인할 수 있는 위치도 부탁드립니다.

먼저, 이 업무에서 최근 일이 잘 안됐거나 불필요한 시간이 많이 들었던 사례 하나를 말씀해 주실 수 있나요?

어떤 일이 들어왔고, 누가 어떤 자료나 도구로 처리하다가 어느 지점에서 문제가 생겼으며, 그 결과 어떤 영향이 있었는지 궁금합니다.
```

## S2. 원하는 변화와 결과의 사용처

```text
방금 말씀하신 [문제 사례]가 개선됐다고 할 때, 누가 어떤 상황에서 결과를 보고 무엇을 다르게 할 수 있어야 하나요?

처음 사용할 수 있는 최소한의 결과 한 가지와, 지금 방식보다 나아졌는지 판단할 수 있는 기준을 알려주세요. 아직 측정하지 않은 수치라면 목표나 추정이라는 점을 구분해 주세요.
```

## S3. 입력 자료·판단 규칙·예외 확인

```text
[판단해야 할 업무 또는 결과]의 기준을 정확히 이해하고 싶습니다.

실제로 사용할 수 있는 입력 예시 하나와, 그 입력에서 어떤 결과가 맞는지 알려주실 수 있나요? 가능하면 비슷해 보여도 다르게 처리해야 하는 예외도 하나 부탁드립니다. 민감정보는 불필요하며 자료 형식이나 항목 예시로 설명해 주셔도 됩니다.

그 판단이 공식 규칙인지 관행인지, 근거를 어디서 확인할 수 있는지도 알려주세요. 값이 없거나 서로 충돌할 때 정해진 처리 방식이 없다면 미정이라고 말씀해 주세요.
```

## S4. 구현 전 최소 범위와 완료 기준 확인

```text
제가 이해한 첫 구현 범위는 다음과 같습니다.
- 해결할 문제와 사용자: [내용]
- 사용할 입력과 만들 결과: [내용]
- 맞아야 하는 대표 사례와 중요한 예외: [내용]
- 이번에는 하지 않을 일: [내용]
- 아직 확인하지 못한 조건: [내용]

이 결과면 실제로 첫 사용을 해볼 수 있을까요? 잘못 이해했거나 꼭 빠지면 안 되는 부분을 짚어주세요. 새 기능을 많이 추가하기보다 이 범위가 업무 목적을 충족하는지와 완료 판단이 맞는지 확인하고 싶습니다.
```

## S5. 애매한 용어·서로 다른 답변 확인

```text
[용어 또는 조건]을 제가 서로 다른 의미로 이해하고 있을 수 있어 확인드립니다.

앞서 말씀하신 내용은 [A]이고, 이번에 말씀하신 내용은 [B]입니다. 적용 대상이나 시점이 달라서 생기는 차이인가요, 아니면 이전 내용을 수정해서 이해해야 하나요?

[구체적인 입력 또는 상황 한 건]에서는 어떤 결과나 다음 행동이 맞는지 알려주시면 그 기준에 맞춰 정리하겠습니다.
```

## S6. 실제 사용·갱신·인계 조건 확인

```text
이 결과를 실제 업무에서 계속 사용하려면 어떻게 갱신하고 전달해야 하는지 확인하고 싶습니다.

원본을 수정하는 사람과 결과를 생성·전달하는 사람, 사용할 수 있는 PC나 시스템, 갱신 시점에 대해 현재 정해진 운영 방식이 있나요? 담당자가 자리를 비우거나 생성이 실패하면 기존 업무를 어떻게 이어가는지도 알려주세요.

받는 사람이 오래된 결과와 최신 결과를 구별하는 방법까지 확인하고 싶습니다. 아직 담당자·실행 권한·승인이 정해지지 않은 부분은 미확인으로 남겨주셔도 됩니다.
```
