# README·데이터에서 질문과 구현 명세까지

접수 창구 운영 검토라는 **합성 사례**로 명세 작성 흐름을 연습합니다. 실제 대회 문제·자료·채점표가 아닙니다. Python 기본 라이브러리만 사용하며, 이 예제는 기본 프로젝트 설치에 복사되지 않습니다.

## 연습하기

1. 별도 연습 폴더에 `task/README.md`와 `task/arrivals.csv`를 복사하고 FDE Kit를 적용합니다. 이 자료는 실제 시험이 아닌 로컬 연습이므로 `standard` 프로필을 사용할 수 있습니다.
2. 아래 요청을 에이전트에게 전달합니다. 아직 코드를 구현하는 단계가 아닙니다.
3. 진행자는 [FACILITATOR.md](FACILITATOR.md)를 별도로 읽고 관련 질문에 맞춰 담당자 답변, 참가자 선택을 차례로 전달합니다. **초기 에이전트에 진행자 자료를 먼저 주지 않습니다.**
4. 명세가 원문 요구, 관측 사실, 담당자 설명, 참가자 선택을 구분하는지 직접 대조합니다. 답변을 받은 뒤에도 미정인 사항과 검사 조건이 함께 갱신되는지 봅니다.

```text
$fde-kit
README와 데이터를 바탕으로 필요한 산출물과 요구사항을 정리하고 구현 세부사항 초안을 작성해줘. 내가 선택할 수 있는 방안들을 설명하고 질문으로 하나씩 확정해줘. 담당자 AI에게 물을 내용은 내가 전달할게.
```

정답 요일을 질문에 넣거나 진행자 자료를 먼저 읽으면 운영 맥락을 발견하는 연습이 되지 않습니다. [선택 후 명세 예](SAMPLE.md)와 평가 기준은 진행자용입니다. 전체 단계를 끝낸 뒤 비교하세요.

## 데이터 관찰 재현

이 폴더에서 다음을 실행합니다. Windows에서는 사용 가능한 `python` 또는 `py`, Linux에서는 보통 `python3`를 사용합니다.

```bash
python facts.py
```

현재 파일의 8행, 월~목 10시·16시 표본, 접수 82건과 행별 초과량 합계 6건을 재계산합니다. 다른 날의 수요나 대기 인원은 추정하지 않습니다. 이 명령은 원본을 읽고 관찰 결과만 출력합니다. 과제 구현이나 에이전트의 질문·명세 작성 품질을 자동으로 검증하지 않습니다.

## 검증 범위

진행자 기준은 산출물 누락, 데이터 범위의 과도한 일반화, 담당자 설명을 숫자로 변환하는 오류, 승인되지 않은 기능 추가, 질문과 확정 규칙의 단절을 점검합니다. 금요일이 아닌 상황과 원문에 충돌하는 답변도 별도 변형으로 시험할 수 있습니다. 실제 수행한 테스트 결과는 저장소의 [검증 기록](../../VALIDATION.md)에 남깁니다.
