# Codex용 프롬프트

필요한 블록 하나만 사용한다. C1 이후에는 같은 대화의 맥락을 이어가며, 여러 단계 작업을 새 대화에서 재개할 때 C8을 쓴다. 설치된 fde-kit와 실제 과제·환경의 제약을 적용한다. 문구·색상·배치와 동등한 내부 구현은 기본적으로 AI에 맡기고, 업무 규칙·제약·필수 기능·권한 등 결과나 위험을 바꾸는 현재 답할 수 있는 중요한 미정 사항을 한 번에 모아서 확인한다. 단순 설명은 대화로, 작은 수정은 관련 파일과 검사만 다루며 전체 절차를 반복하지 않는다.

## C1. 문제 정의 시작

```text
$fde-kit

지금은 문제 정의 단계다. 내가 업무 담당자와 대화하면서 해결할 문제와 완료 기준을 구체화하도록 도와줘.

과제 또는 최초 요청: [원문]
알려진 시간·환경·제출 조건: [알려진 내용만. 모르면 미확인]

먼저 실제 과제의 README·제출 안내·기존 프로젝트 문서와 제공 입력을 읽어줘. 키트의 README나 예제를 과제 원문으로 혼동하지 마. 자료가 없으면 위치나 연습용 과제 설명을 요청하고 없는 요구를 만들어내지 마. 아직 구현을 요청하지 않았으므로 분석과 문제 정의에 집중해줘.

기존 BRIEF에 구현 명세 초안을 작성해줘. 요구 ID/원문 위치 → 필수 산출물·동작·입출력 조건 → 데이터 근거·한계 → 구현 후보·장단점 → 명시됨/미정/확정/위임 상태와 질문 상대 → 검사 조건을 연결해줘. 제출 경로·형식, 시간·환경·권한 조건도 포함해줘. 실제 데이터의 구조·대표 행·누락·중복·단위·시각뿐 아니라 기간·집단·채널의 관측 범위를 확인해줘. 자료에 없는 상황을 0이나 문제없음으로 보지 마. 아직 미정인 항목도 초안에 표시하고 인터뷰가 끝날 때까지 작성을 미루지 마.

최적화가 필요한 과제라면 같은 명세에 결정변수, 목적·단위·우선순위, 강제 제약과 경계값, 입력 규모와 전처리·후보 제한의 영향을 정리해줘. 대응하는 표준 문제 유형과 가능한 해법을 조건 적합성·품질 근거·시간/메모리·구현 위험·설치 가능 여부로 비교하고, 기준안·개선법·중단 조건·독립 검사를 연결해줘. 업무 목표의 가중치나 허용 오차를 임의로 만들지 말고 중요한 미정만 확인해줘. 최적화와 무관한 요청에는 이 절차를 추가하지 마.

그다음 문서와 입력으로 알 수 없는 실제 실패·수요 변화·기록되지 않는 상황·운영 제약은 담당자 AI에게 물을 중립적인 질문으로 준비해줘. 질문 상대와 답변이 바꿀 명세 ID를 밝혀줘. 특정 요일이나 임계값을 가정하지 마. 내가 전달해야 하는 환경이면 돌아온 답변을 기다려줘. 업무 결과를 바꾸는 구현 방식·범위·중요 기본값은 대안·장단점·추천 이유를 제시해 내가 선택하도록 해줘. 문구·색상·배치와 동등한 내부 구현은 기존 요구·접근성·업무 의미 안에서 기본 위임할게. 현재 답할 수 있는 중요 질문을 한 번에 모아 번호를 붙이고 사실 질문의 답변 선택지는 지어내지 마.

원문 요구, 담당자 답변과 네 제안을 구분하고 수치·승인·배점을 만들어내지 마. 질문마다 근거가 되는 자료나 빈칸, 답할 사람, 답에 따라 달라질 계획 항목을 밝혀줘. 필수 목표·제약·입력의 미확정을 먼저 해결하고 그 결정에 의존하는 세부 선택으로 이어가줘. 질문·답변·출처·미정/확정/위임 상태는 DECISIONS, 현재 명세와 전체 계획은 같은 BRIEF에 갱신해줘. 대회라면 실제 안내와 competition 지침을 먼저 적용해줘.

첫 답변은 필수 산출물·요구사항, 중요한 데이터 사실과 한계, 미정 항목을 표시한 전체 서비스 계획 초안을 보여준 뒤 필요한 중요 질문이 있을 때만 현재 답할 수 있는 질문을 한 번에 모아서 제시해줘. 앞선 답변에 의존하는 질문은 그 답변 후에 이어가줘. 이미 명시·확정·기본 위임된 사항으로 질문을 만들지 마. 답을 받을 때마다 바뀐 규칙이 기능·데이터·사용자 흐름·검사에 어떻게 반영되는지 보여줘.

질문이 끝나면 첫 구현 범위를 넘어 전체 요청을 수행할 구현 계획을 완성해줘: 목표·성공 기준과 필수/제외 범위, 처음부터 끝까지의 사용자 흐름과 예외, 입출력·데이터 구조, 핵심 계산·목적·제약, 필요한 화면/보고서·인터페이스·저장, 구현 순서·의존관계, 정상·경계·실패 검증 사례와 남은 가정. 과제에 필요 없는 웹·DB·새 파일은 추가하지 마. 각 필수 요구가 구현과 검사에 연결되는지, 근거 없는 기능이나 서로 충돌하는 결정은 없는지 검토해줘. 질문이 불필요하면 이 계획을 바로 제시해줘.

전체 계획이 구현 가능한 상태인지, 중요한 미확정 때문에 어느 부분이 아직 막혀 있는지 명시해줘. 이미 명시·확정·위임된 사항을 다시 묻지 말고 내부 구현 선택은 맡길게. 이번 요청은 문제 정의와 계획이므로 계획을 전달하고 제품 코딩은 시작하지 마.
```

## C2. 담당자 답변 반영·다음 질문

```text
업무 담당자의 추가 답변이야.
[답변 원문과 관련 질문·자료 위치]

과제 원문과 기존 이해에 대조해서 새로 확인된 내용, 바뀐 내용, 충돌을 짧게 정리해줘. 이 답이 필수 기능·제약·목표·검사·구현 순서 중 무엇을 바꾸는지 짚어줘. 원문과 충돌하면 어느 조건을 적용할지 확인하고 임의로 덮어쓰지 마. 상대가 확정하지 않은 규칙·수치·운영 승인을 사실로 바꾸지 마.

질문 ID·답변 주체·출처와 영향을 받는 구현 명세 ID를 기록해줘. 담당자 설명은 관측값이나 내 구현 선택과 구분해줘. 관련 명세의 데이터 한계·구현 후보·미정 상태만 갱신하고, 중요한 업무 선택이 남은 경우 장단점을 제시해 내 선택을 기다려줘. 기본 위임된 문구·색상·배치로 후속 질문을 만들지 마. 선택이 확정되면 규칙과 검사 조건을 함께 갱신해줘. 담당자가 혼잡을 알려줬다고 실시간 알림·수요 배수·증원 인원을 자동으로 만들지 마.

답변이 확정한 범위만 기록하고, 남은 중요한 업무 미정 사항이 있을 때만 현재 답할 수 있는 질문을 한 번에 모아서 이어가줘. 선택지가 있으면 장단점과 추천 이유를 설명해줘. 한 답으로 관련 없는 업무 규칙까지 정하지 마. 수요 집중만 확인했다면 필요한 실패·손실을 구체화해줘. 새 정보마다 기능을 추가하지는 마.

현재 전체 계획에서 무엇이 바뀌었고 무엇이 아직 미정인지 보여줘. 필요한 답변이 모두 명시·확정·위임됐다면 같은 BRIEF에서 C1의 전체 구현 계획을 종합해줘. 모든 필수 요구의 구현·검사 연결, 데이터와 규칙의 일관성, 추가 기능의 근거를 확인하고 준비 완료 여부와 남은 가정을 밝혀줘. 일부 작업만 준비된 것을 전체 계획 완료로 말하지 마. 계획 단계라면 계획을 전달하고 제품 코딩은 시작하지 마. 이미 구현을 요청한 범위에서는 준비된 독립 작업을 계속할 수 있어.

이미 구현 중이라면 변경이 요구사항인지 단순 설명인지 구분하고 영향받는 코드·자료·검사를 짚어줘. 실제 요구가 바뀌면 BRIEF를 갱신하고 `fde.py update`로 기존 작업의 바뀐 항목과 변경 이유를 반영한 뒤 검증 상태를 확인해줘. 답변 전달만으로 새 구현 범위가 승인됐다고 가정하지 마.
```

## C3. 범위 확정·구현 또는 분석 실행

```text
$fde-kit
아래 범위로 실행해줘.

목표와 사용자: [누구의 어떤 일을 바꿀지]
입력과 산출물: [자료 위치, 결과 경로·형식]
완료 조건: [확인된 정상 사례와 중요한 예외의 기대 결과]
제약과 제외 범위: [시간·환경·권한·하지 않을 일]

실제 과제 README·입력·기존 코드와 합의한 범위를 먼저 대조하고, 필수 기능 누락이 없는 가장 작은 입력→처리→사용 가능한 결과 경로부터 완성해줘. 화면·저장·내보내기는 요구된 범위만 연결해줘. 필수 조건을 만족하는 단순한 기준 구현을 만든 뒤, 확인된 핵심 문제를 개선하고 전후 결과를 비교해줘. 최적화 자체가 필수라면 첫 구현에도 포함하고, 검증되지 않은 최적해를 주장하지 마. 필수 검증·보안·수용량 같은 강제 조건을 나중으로 미루지 마.

최적화 작업이면 확정된 모형과 같은 강제 조건을 만족하는 기준안부터 만들고 개선해줘. 탐색 시간을 제한하고 가장 좋은 검증된 유효 해를 기존 산출물 위치에 보존해줘. 시간 초과를 해 없음으로, 유효한 해를 증명된 최적해로 바꾸어 말하지 마. 전처리·근사·후보 제한과 품질 근거를 공개하고 같은 입력·목적·제약으로 비교해줘. 검증 명령 실행 중에는 등록된 산출물을 바꾸지 마.

구현 전에 관련 명세 ID별 원문 요구·데이터 근거·담당자 답변·내 선택·검사 조건이 연결됐는지 확인해줘. 다음 작업에 필요한 미정 사안이 남아 있으면 그 부분부터 질문하고, 확정 또는 명시적으로 위임된 규칙만 코드와 검사 기대값으로 옮겨줘.

내장 도구는 실제 입력·규칙에 맞고 작업을 줄일 때만 사용해줘. 문구·색상·배치와 동등한 내부 구현은 기본 위임하며 기존 요구·접근성·업무 의미를 지켜줘. 업무 규칙·제약·필수 기능·권한·입력 허용 여부처럼 현재 답할 수 있는 중요한 미정 사항을 한 번에 모아서 확인하고, 그 답을 받기 전에 해당 규칙을 코드·검사 기대값으로 정하지 마. 독립 작업과 위임된 범위는 진행해줘. 작은 수정이면 관련 파일·영향받는 검사만 다루고 새 인터뷰·전체 계획·전체 검사·handoff를 자동 반복하지 마. 등록된 파일 변경의 검증 무효화와 필요한 재검증은 유지해줘.

추가 요청은 기존 구현·테스트·산출물·문서를 먼저 찾아 갱신해줘. 작은 단일 담당 작업은 같은 BRIEF와 작업 계약을 사용하고 별도 작업 폴더·번호 붙인 사본·계획서·분석서·요약서를 요청마다 만들지 마. 설명·상태·검토는 대화로 답하고, 문서는 요청되거나 제출에 필요한 경우만 만들어줘. 새 소스·검사는 실제 책임 분리나 반복 사용에 필요할 때 추가하며 필요한 분리를 억지로 합치지는 마. 원문 README와 제공 입력은 보존해줘.

일회성 점검·실험은 직접 만든 임시 디렉터리에서 수행하고 종료 전에 경로·소유권·참조를 확인해 정리해줘. 반복 사용할 검사는 기존 테스트에 통합해줘. 정리 대상으로 검증 로그·state·manifest와 참조 산출물, 사용자 파일을 포함하지 마. 현재 작업이 만든 새 파일 중 유지할 이유 없는 임시 파일을 남기지 말고, 정리에 실패했다면 남은 위치를 알려줘.

관련 요구 문서·입력·실제 구현 파일·설정·검사·산출물을 빠뜨리지 말고 등록해줘. 이미 승인한 범위에서는 매 단계마다 다시 허락을 묻지 말고 필요한 검증과 사용 안내까지 마쳐줘. 범위 밖 배포·외부 전송·새 에이전트 사용 권한까지 가정하지 마.

첫 실제 검사를 verify --handoff로 기록해줘. 구현·산출물 생성은 검사 전에 끝내고, 진행 메모는 DECISIONS에 둬. 마지막에는 결과 위치, 실제 검사 결과, 남은 한계와 운영 조건을 짧게 알려줘.
```

## C4. 결과 검증·구체적인 약점 확인

```text
$fde-kit
현재 결과가 원래 요구와 완료 조건을 충족하는지 검증해줘.

현재 파일과 기존 검증 근거부터 대조해줘. 이미 유효한 검사를 이유 없이 반복하지 말고, 바뀐 부분이나 아직 확인하지 못한 중요한 위험을 검사해줘. 생성 명령 성공이나 파일 해시만으로 업무 결과가 맞다고 결론 내리지 마.

원래 요구에서 독립적으로 정한 정상·경계·실패 사례를 실제 결과와 비교해줘. 그럴듯한 오답을 통과시킬 위험이 크면 원본을 보존한 복사본에서 중요한 값 하나를 바꿔 검사가 거부하는지도 확인해줘. 체크를 통과시키려고 요구나 기대값을 임의로 바꾸지 마.

최적화 결과라면 원본 입력·규칙으로 제약과 목적값을 독립 재계산해줘. 유효성·최적성·해 없음의 증명 범위를 구분하고 근거 있는 상하한·격차만 보고해줘. 제한한 후보나 근사 모형에서의 최적성을 원문 전체 문제로 확대하지 마. 최적성 증명이 필수인데 유효성만 확인됐다면 미완료로 남겨줘. 탐색기의 제한시간 종료와 kit 검증 명령의 실패·시간 초과를 혼동하지 마.

보고는 중요한 순서로: 구체적인 약점 위치 → 왜 위험하고 어디까지 영향을 주는지 → 확인 근거 → 필요한 수정 또는 다음 검사. 실제로 발견한 문제만 말하고, 수행하지 않은 검사는 미확인으로 남겨줘. 별도 보고서를 요청하지 않았다면 대화로 답하고, 일회성 검사 복사본은 직접 만든 임시 공간에서 정리하되 검증 근거는 보존해줘. 이번 요청은 검증이며 범위를 늘리는 재설계는 먼저 제안해줘.
```

수정 후 원래 실패 사례와 영향받는 중요한 동작을 실제로 검사해줘. 실패 로그를 지우거나 이전 성공 기록으로 대체하지 말고, 현재 코드·입력에 대한 검증과 handoff를 갱신해줘. 마지막에는 원인, 바꾼 부분, 확인 결과와 남은 불확실성만 짧게 정리해줘.

## C7. 세션 종료·인계

```text
$fde-kit
여기까지 작업을 정리해서 다음 세션이 이어갈 수 있게 해줘. 새 기능은 만들지 마.

현재 파일과 실제 검증 상태를 확인하고, 목표·합의한 범위·산출물 위치·검사 근거·남은 문제·다음 행동 하나를 기존 기록에 남겨줘. 요구가 바뀌지 않았다면 진행 보고 때문에 BRIEF를 다시 쓰지 말고 DECISIONS를 사용해줘. 중복 요약 문서를 추가하지 마.

지금 답을 기다리는 질문, 아직 묻지 않은 미정 사항, 이미 확정된 답변과 출처, 명시적으로 위임한 범위도 DECISIONS에 유지해줘. 바뀐 결정은 이전 답변을 지우지 말고 무엇으로 대체됐는지 남겨줘.

반복 사용할 결과라면 누가 어느 환경에서 언제 원본을 수정하고 생성·전달하는지, 최신 결과를 어떻게 구별하는지도 짧게 남겨줘. 확인되지 않은 운영 책임이나 권한은 미확인으로 표시해줘. 현재 상태에 맞는 handoff를 생성하고 다음 세션에서 처음 읽을 위치를 알려줘.
```
